# MotorNote V20.1 — Interface refinement

Baseline: production release 1d538bf; schema V9. Preview-only implementation. No engine, persistence, manual corpus, authentication or deployment changes.

## Phase 1 — Navigation and visual hierarchy

- Five consistent destinations: Home, Projects, Capture, Inventory, Manuals; secondary Garage destinations remain in the header More menu. Manual search, favorites, recent pages and vehicles remain accessible within the manual workspace. Direct manual viewer retains its focused controls.
- Same-origin Garage links accept only known presentation routes (dashboard, projects, inventory, capture, existing specs). Capture opens existing forms, not a new data pathway.
- Next Best Action remains first; existing Execute/Review/Waiting/History projections become count tiles with detail dialogs. Counts describe rows, not distinct projects or safety findings.
- Consistent dark palette and amber action color; compact Manual home moves technical library statistics into a disclosure. Existing light theme remains supported.
- Preview CI must verify all existing regressions, shared navigation, cross-workspace capture and mission dialog behavior before acceptance.

## Remaining presentation work

Project detail tabs, workshop display, save/offline indicator, attachment viewer and search refinements. Preserve existing forms and safety checks. No production publication without explicit approval.

## Phase 2 — Tabbed project workspace

- Overview retains the next action, readiness, guided repair controls, budget, actual cost and completion gates. Work contains existing scheduling, notes, tasks and milestones. Parts contains existing inventory and procurement. Manual contains factory procedures. Records contains receipts, actual expenses and project management.
- Selection resets to Overview when a project opens; the Save Project Workspace action stays available across views. No data fields, workflow rules or engine methods changed.
- Existing browser and unit tests remain required; new tests verify tab isolation and preserved actions.

## Follow-on milestone: V20.2 — Consumables & Replenishment

User-requested scenarios: 2006 Scion xB washer reservoir is empty; shared shop rags are running low. These are requirements/examples, not seeded personal records.

- Report Low/Empty through Capture; distinguish vehicle reservoir level from garage stock. Unknown quantities must stay unknown. Reuse inventory stock, reorder targets, linked purchasing, partial receipts and ledger transactions, not a separate purchasing engine.
- Low/empty reports appear immediately adjacent to Next Best Action and are eligible for dynamic prioritization. Empty vehicle consumables should outrank routine work but not urgent safety issues, data failures or confirmed critical repairs. Do not duplicate the same item if already displayed as Next Best Action.
- Order does not resolve a vehicle shortage; receiving stock returns it to Execute Now for actual refill. Resolve only after confirmed refill. Garage supply shortages resolve only when sufficient stock is confirmed. Deduplicate orders and actionable rows; keep waiting and overdue orders visible until resolved.
- Refill/consumption should have explicit quantity/unit when deducting stock, preserve ledger consistency, and never treat refill as a repair project. Qualitative levels and unknown amounts allowed without invented deductions. No automatic purchase or unverified estimates.
- Separate functional release after V20.1 acceptance. Design backup/restore compatibility, lifecycle, safety and regression tests before implementation.
