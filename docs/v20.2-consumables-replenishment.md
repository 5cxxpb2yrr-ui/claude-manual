# V20.2 — Consumables & Replenishment
Baseline: consolidated V20.1 main dbbfe6a. Preview only; no personal records seeded.

## Phase 1 — lifecycle
Pure report/resolve/project functions, with synthetic test coverage. Reports identify vehicle reservoir or shared garage supply, optional verified inventory link and unit, optional numeric garage stock target; unknown quantities remain null. One open report per scope/vehicle/name. Read canonical available stock (quantity less reserved) and explicitly linked open vendor lines. Receipt never resolves a vehicle report; actual refill confirmation does. Garage target requires available stock at or above target and confirmation.

## Phase 2 — UI and storage
- Capture → Report low / empty consumable; Mission Control shows active reports adjacent to Next Best Action without repeating that primary action. Empty vehicle report ranks 83, other empty 74, low 66; higher confirmed maintenance, urgent findings and data-integrity errors retain their existing ranking. Waiting ranks 44, overdue 81.
- Report is independent from the quantity of garage stock. Select an existing stock record to verify unit and fitment. Purchase button opens the existing vendor form with verified stock link where available; quantity and price require explicit entry. Unknown stock must be linked by the user after receiving if no existing record was linked. General order records remain visible.
- Explicit refill confirmation closes vehicle report; optionally deduct actual quantity from available linked stock. Quantity/unit and report identity are passed to canonical save/ledger reconciliation in the same state transaction. Reserved stock cannot be consumed. Failed save rolls back both report and stock.
- Compatibility decision: use a versioned extension on the existing vehicle collection, because the pinned V9 recovery build drops unfamiliar top-level collections but preserves vehicle fields. Vehicle records are stored on the relevant vehicle; shared reports have null vehicle ID and are stored on the deterministic first vehicle as a carrier only. No schema bump, fake inventory record, service log, or repair project. Restore validates report scope and duplicates before applying candidate state. Full backup replacement of vehicles replaces their embedded reports; previous state is safety-snapshotted.
- The new module joins the versioned offline shell; pinned V9 still has twelve resources, new shell thirteen. Browser tests cover Capture, quantified refill, ledger integrity, offline reports and preservation of both open/resolved reports through V9 rollback. Tests are committed, not yet accepted.

## Remaining acceptance

Consider explicit report-to-order links for unlinked purchases and better deduplication of waiting actions in a follow-up before production acceptance. No automatic purchasing or speculative amounts.
