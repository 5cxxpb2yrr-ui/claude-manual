# V20.2 — Consumables & Replenishment
Baseline: consolidated V20.1 main dbbfe6a. Preview only; no personal records seeded.
## Phase 1 (this PR)
Pure report/resolve/project functions, with synthetic test coverage. Reports identify vehicle reservoir or shared garage supply, optional verified inventory link and unit, optional numeric target; unknown quantities remain null. One open report per scope/vehicle/name. Read canonical available stock (quantity less reserved) and explicitly linked open vendor lines. Receipt never resolves a vehicle report; actual refill confirmation does. Garage target requires available stock at or above target and confirmation. No automatic purchasing or inventory deduction. Known quantity consumption is deliberately rejected by the qualitative resolver; future atomic stock transaction required.
## Phase 2 — Persistence and UI
Integrate Capture report dialog, replenishment panel adjacent to Next Best Action, mission rows and navigation. Priority: empty vehicle report 83, other empty 74, low 66; higher confirmed maintenance, urgent findings and data-integrity errors retain their current ranking. Waiting rank 44, overdue 81. Avoid duplicate adjacent card if it is already Next Best Action; retain unrelated order lines and general order visibility. Require explicit existing stock selection; unknown quantities cannot invent zero stock or order amounts. Link newly received stock after user verifies identity and units. No repair projects for refills.
Persistence is not yet implemented: the pinned V9 rollback serializes only recognized top-level collections. Before shipping, choose a versioned storage/rollback contract that preserves reports, including explicit backup/restore validation and legacy recovery behavior. Never silently drop report records on rollback. Quantified refill must commit report and inventory ledger atomically, respect reservations and units, and rollback on failed write. Add browser coverage for actual Capture, reload, offline, partial receiving, reordering, duplicate prevention, backup and recovery. Existing 164 tests and both browser engines remain required.
