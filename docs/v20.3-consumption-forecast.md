# V20.3 phase 3 — Consumption-based reorder forecasting
Base: merged V20.3 phase 2 main 002da15. Preview only.
- Capture → Record stock used accepts a stock item, actual quantity in its recorded unit, and reason. Existing reservation floor and ledger integrity checks protect stock; canonical save commits the deduction and explicit usage evidence together. Failed saves roll back the balance. Vehicle reservoir refills continue through the existing consumable workflow.
- Forecast looks at the last 90 days of explicit ledger-backed, unit-matched usage or confirmed quantified refill events, using only currently identifiable stock. Requires at least three distinct usage dates spanning 14 days and last use within 30 days. Record merges/removal/recreation reset comparable history. Corrections, purchases, reservations and qualitative reports are not usage.
- Estimate rate from usage after the first observation divided by elapsed time since that observation. Available stock excludes reserved quantities. Review if estimated availability is 14 days or less; advisory 30-day target rounded up to whole recorded stock units. These are initial design defaults, not personalized buying quantities or guaranteed depletion dates.
- Storage & reorder shows history/insufficient evidence, usage rate and estimated days remaining, with a link to review existing reorder settings. Shopping adds a review-only prompt where there is no existing target, related report, repair demand or incoming linked order. Estimates do not automatically set reorder targets, create orders, or allocate stock. Incoming orders and planned use may alter actual availability; inspect them before changing settings.
- No schema changes. New unit and actual offline usage browser tests; preserve all previous rollback assertions. CI and isolated preview acceptance required before publication.
